# Handoff — agent-driven improvement loops, 2026-08-29

Written at the end of an unattended overnight session. It tells the next
worker — human or agent — what exists, what is proven, what is not, and what to
do next. Read it top to bottom before touching a branch.

## 1. The objective this work serves

`ai-experiments` must be the library an agent drives from one chat message: a
user states a research goal in Claude Code or Codex, the agent loads one skill,
and the harness runs as many improvement rounds on Ray as the budget allows,
until the objective is met. That is issue #34, with the design in
`docs/superpowers/specs/2026-08-29-agentic-improvement-loop.md` and the plan in
`docs/superpowers/plans/2026-08-29-agentic-improvement-loop.md`.

Every task in that plan is checked off. The remaining work is not "build the
loop"; it is "land the loop and prove it against the real cluster".

## 5. Environment constraints on this machine — read before running anything

- **Never run `ray stop`.** A docker Ray cluster (`ray-head`, `ray-worker-cpu-1`,
  `ray-worker-cpu-2`) and a kind cluster (`workbench-local-control-plane`) run
  all the time on this host. `ray stop` kills them. Stop only iax's own Ray
  processes, filtered by the repo `.venv` path.
- **Host ports 8265 and 5000 are taken** by the kind cluster (Ray dashboard) and
  MLflow. `tests/integration/compose.yaml` uses `network_mode: host` on exactly
  those ports, so it cannot start while the kind cluster is up.
- **The available Ray head is on 8266 and runs Ray 2.47.0**, while the
  integration client pins **2.37.0**. The Jobs API refuses that pairing, so the
  suite would fail even with free ports.
- Run `uv run --extra dev python -m pytest tests` as the gate. Report the 16
  integration skips as expected.
- Never commit `team.json`, `.orquestalite/`, `.venv/`, `.agents/`, or
  `manual_test/`. `.claude/skills/using-orq-lite` is a symlink to orq-lite's own
  installed skill and stays untracked.
- `uv.lock` changes only through `uv`. Never `git add -A`.
- A run directory may hold `repro/diff.patch`, a diff of the worktree. Read it
  before publishing it anywhere.

## 6. Remaining work

### Ticket 1 — Land the stacks

Review and merge the 13 PRs bottom-first in the order of §2. After each stack,
run the gate. Close `integration/all` (#47) once both stacks are on `main`; it is
a preview, never the thing to merge.

### Ticket 2 — Make the Ray integration suite runnable on a host whose cluster is
already up

The suite is unrunnable here for two independent reasons, and both are fixable
in the repo rather than in the user's environment:

- The compose file claims host ports 8265 and 5000 unconditionally. Make the
  ports configurable, or let the suite target an already-running cluster by
  address instead of starting one.
- The client pins Ray 2.37.0 while the reachable head runs 2.47.0. Decide the
  supported range, state it, and make the version mismatch a clear skip reason
  rather than a Jobs API error.

Done means: on this host, with the kind cluster up and the Ray head on 8266,
the integration tests either run or skip with a message that names the reason.

### Ticket 3 — Prove the closed loop against the real cluster

With Ticket 2 landed, run `iax loop` with `backend: ray` against the host's Ray
head on port 8266, driven by a real agent, and record the round rationales.
Done means: a rounds file that shows the agent reading a real trial failure and
changing its proposal because of it.

### Ticket 4 — Codex parity for the chat experience

The skill is written for Claude Code. Codex reads `AGENTS.md`, which does not
exist on `main`: it arrives with the agentic stack, so this ticket verifies it
rather than creates it. Check that a Codex session, given only `AGENTS.md`, can
state a goal and drive `iax loop` to a result without reading the Claude skill.
Fix whatever it cannot reach.
